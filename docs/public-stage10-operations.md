# Stage 10 公网实盘操作手册

## 范围

public Stage 10 仅支持现有受控 Binance Spot 生产链。OIDC 登录不是实盘授权；研究、AI 评审、回测或研究包也不能产生执行权。

自动化测试不得提交真实生产订单。真实验收必须在独立环境由账户所有者显式执行。

## 前置条件

- 当前用户为 `active`，且最近 5 分钟完成 OIDC 重新认证。
- 租户设置中存在专用生产交易凭据；服务器环境变量不作为回退。
- API Key 开启读取与 Spot 交易，关闭提现、内部/通用划转、Margin、Futures 和 Options。
- 生产交易总开关、Stage 10 权限预检、策略绑定、风险上限和账户覆盖全部通过。
- 急停处于可恢复状态，无未决对账和账户指纹冲突。
- PostgreSQL 生产 lease 可获得。

## 配置与重新认证

1. 在设置页保存当前租户专用生产 Key/Secret。若返回“需要重新认证”，进入 OIDC 重新认证后回到原 URL，再次提交。
2. 不要复用 Sandbox 或生产只读 Key，不要让同一生产账户被两个租户配置。
3. 保存后检查页面只显示配置状态和脱敏指纹，不显示明文密钥。

更新或清除任一生产 Key/Secret 会先暂停现有 live 会话并撤销 Stage 10 控制；保存完成后必须重新预检、重新认证和重新授权。

## 开启或续期

1. 在执行中心完成最新凭据预检和权限复核。
2. 检查急停、账户覆盖、策略版本、市场、周期、单笔/批次上限和未决订单。
3. 近期重新认证后输入确认并开启或续期生产会话。
4. 服务端声明跨租户活动账户指纹并获取 lease；任一冲突必须在外部下单前阻断。
5. 会话开启不代表立即下单。每次新委托仍重新检查权限、账户、风险、行情新鲜度和稳定 `clientOrderId`。

## 急停

- 发现权限漂移、未知订单、账户变化、异常行情或策略证据漂移时立即触发急停。
- 急停阻断新行情评估和新委托，但不会删除、撤销事实或停止已有未决订单的只读对账。
- 恢复控制必须再次完成最近 5 分钟 OIDC 重新认证，并重跑权限、账户和风险检查。
- 不得通过修改数据库、关闭 CSRF、跳过 lease 或换新 clientOrderId 绕过急停。

## 未决订单对账

- 始终使用原 `clientOrderId` 查询；未知状态不得补单。
- 用户退出登录、会话过期、暂停或急停后，后台仍只读查询已有委托直到终态。
- 成交以稳定交易 ID 幂等入账；重复回调或重启不能生成第二笔成交。
- 对账未完成时不得切换执行模式、迁移数据或重新授权同一账户。

## 账户冲突

活动生产账户指纹由服务端通过只读账户响应中的 Binance UID 派生，并跨租户唯一；同一账户的不同 API Key 仍会冲突。若出现冲突：

1. 暂停两个租户的新委托。
2. 完成所有未决订单只读对账。
3. 在旧租户撤销生产控制并释放账户声明。
4. 在目标租户重新认证、重新配置和重新授权。

不要删除审计事件或直接修改 claim/lease 表。

## 事故记录

保留以下脱敏证据：owner ID、控制/授权 ID、策略与快照 hash、账户指纹、clientOrderId、权限布尔值、急停/恢复时间、对账终态和相关审计事件 ID。不得记录 Key、Secret、余额明细或交易所原始认证响应。

## 关闭实盘

1. 暂停新评估并触发生产控制撤销。
2. 等待所有已提交订单终态对账。
3. 在 Binance 撤销或轮换 API Key。
4. 清除租户生产密钥设置。
5. 复核账户 claim 和 lease 已释放，保留历史审计。

研究包导出/导入不能代替上述关闭与恢复流程。
