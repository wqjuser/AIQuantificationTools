# Stage 10 开放受控的自动生产现货路由

用户于 2026-07-26 明确确认启用生产实盘模式。本决策对 ADR-0020 的“生产网络与下单始终关闭”增加一个受控例外：原有 Stage 9 单笔候选和手动执行尝试继续失败关闭；AI 涨跌幅自动交易可以在独立生产会话中提交 Binance Spot 生产委托。

生产会话默认关闭，必须同时满足 `AIQT_ENABLE_PRODUCTION_TRADING=true`、专用生产交易凭据已配置、五分钟内完成读取/现货交易权限核验、Binance 返回 `ipRestrict=true`、Margin/Futures/Options/提现/内部划转/通用划转权限全部关闭、Stage 10 持久急停已人工恢复，并在自动交易区填写实名操作人和确认真实资金风险。一次确认最多有效八小时；急停撤销、控制 ID 变化或会话过期立即阻止新委托。

首版只允许 `BTC/USDT` 市价单，单笔新增风险不超过 `10 USDT`；关闭本策略既有持仓时按原始成本校验，不因价格上涨阻止退出。系统继续执行止损、止盈、当日亏损和每小时成交次数限制。AI 低置信度或“无法保证不亏”不作为拒绝交易条件，但数据、余额、交易所规则、权限、急停和未完成对账仍然阻断。

每根 K 线与方向生成稳定 `clientOrderId`。生产路由提交前先按该 ID 查询；查询确认不存在才创建，提交异常后再次查询，仍不确定则进入 `reconciliation_required` 并停止后续自动委托。订单与成交审计只保存脱敏请求和标准化证据，不保存密钥、余额或交易所原始响应。

测试网与生产自动交易在调用外部路由前，必须按稳定 `clientOrderId` 幂等记录脱敏提交意图，并在各自策略状态中保存已确认意图水位。若进程在交易所接受委托后、策略状态保存前退出，重启必须把未确认意图恢复为 `submission_pending`，按原 ID 只读查询并收口终态；不得因行情已经进入下一根 K 线而生成新 ID 或创建下一笔委托。

生产会话开启后的每笔新委托不能沿用会话开始时的权限快照。在稳定 `clientOrderId` 查询确认订单不存在后、写入 `submission_pending` 和调用创建接口前，Stage 10 必须再次读取 Binance API restrictions；`ipRestrict`、读取/现货交易权限或任一 Margin/Futures/Options/提现/划转危险权限发生漂移时立即阻止创建。查询与对账已经存在的委托继续允许，以免权限漂移掩盖真实成交事实。

API 后端运行器必须继续收口 `submission_pending`、`open`、`partially_filled` 和 `reconciliation_required` 自动委托，即使操作者已暂停监控、生产会话过期或 Stage 10 急停已触发。该路径只按原 `clientOrderId` 查询既有订单，不允许创建、补单、改 ID 或恢复新委托权限；终态成交数量只计入策略账本和审计一次。执行模式切换必须等待策略持仓与未决订单完成对账。执行中心可人工触发同一只读对账，但必须使用独立于“立即评估”的请求路径；即使后台恰好先完成对账，该请求也只能返回当前快照，不能继续行情评估或创建新委托。

测试网与生产成交的交易 ID 必须由原 `clientOrderId` 稳定派生，成交审计按该 ID 幂等写入。若进程在成交审计提交后、策略状态保存前退出，重启后必须复用已经存在的审计事件及原成交时间，再完成同一笔策略账本入账；不得生成随机交易 ID 或第二条成交审计。

自动市价买入必须使用 CCXT `create_market_buy_order_with_cost` 按报价币金额提交，不能再用参考价换算的基础币数量冒充资金上限；精度归一后的报价金额仍不得超过单笔风险预算。标准化订单证据保留交易所返回的实际 `cost` 与 `fee / fees`。报价币手续费直接影响现金，基础币手续费直接减少净持仓；响应缺失手续费或手续费使用当前无法估值的第三方币种时，才使用既有费率估算，并在交易证据中固定 `feeEstimated=true`。

测试网与生产模式每次进入行情和 AI 评估前，必须通过 CCXT 只读查询确认交易所可用基础币覆盖本地策略持仓、可用报价币覆盖下一笔新增风险预算，且当前交易对不存在本地未记录的 `aiqt-auto-` 自动挂单。检查异常或任一项不覆盖时以 `account_mismatch` 停止新决策和委托。系统只持久化覆盖布尔值、孤儿自动挂单数量与检查时间，不保存真实余额或订单号。首版只做单向覆盖，不要求交易所账户总资产等于策略账本；账户中的其它人工资产不会被本策略接管。

自动交易后端对固定 `BTC/USDT · 1m` 每轮请求 7 根 K 线。CCXT 返回的最近 K 线在下一周期开始前可能仍未完成，因此系统按 UTC 开始时间剔除未收盘 K 线，只把最近 6 根完整 K 线交给策略。最新完整 K 线收盘超过两个周期或完整数量不足时记录 `data_blocked`，并在账户查询、AI 决策和委托之前结束本轮。`DataQuality.is_complete` 只说明适配器响应结构完整，不能替代交易时效检查。

后端运行器每轮必须持久化脱敏运行心跳，包括累计轮次、最近周期、最近成功、最近异常和连续失败次数。异常后的下一轮成功会清零连续失败，并只在当前状态仍为 `evaluation_error` 时恢复为监控；不得覆盖账户、风险、数据或订单阻断。执行中心超过三个配置周期且至少 90 秒未收到心跳时提示中断。该证据不自动重启运行器、不恢复授权，也不触发 AI 或委托。

执行中心的系统提醒使用浏览器原生 Notification API，并且只能由操作者点击后申请权限。未决委托、账户或风控异常、状态 API 读取失败、后台停止、连续失败和心跳中断按稳定状态键各提醒一次；成功恢复读取或恢复正常后才允许同类异常再次提醒。读取故障使用独立前端状态，参数校验和人工操作失败不能伪装成后台断线。页面关闭后不承诺通知，也不增加第三方推送、后台服务或任何自动评估、对账、重启和委托动作。
