# M5 组合风险评估延伸 Stage 4 账户回放

M5 不新建组合引擎、订单状态机或数据库表。它以既有 `aiqt.stage4PortfolioWorkflow` 为唯一输入，从 Stage 4 的组合回测、纸面委托、人工审批、模拟成交和账户回放中派生当前组合、目标组合和候选调仓，再把组合级风险结论写入既有 `AuditEventStore`。

## 决策

服务端从已审计 Stage 4 工作流读取：

- 组合目标、初始资金、市场和腿位；
- 纸面账户现金、持仓、最新价格和权益；
- 组合回测的最大回撤、相关性和协方差风险贡献；
- 批次、审批、模拟成交及 paper-only 安全边界。

用户只补充现有工作流没有表达的组合分类、当日观测和限额：

- 每个标的的行业与币种；
- 当日损失和当日交易次数；
- 最大回撤、当日损失、交易频率、总暴露、单一标的、行业、市场、币种、相关性和风险贡献限额。

评估同时记录每个标的的当前权重、原目标、风险调整目标、漂移和候选调仓，并单列当前、目标与调整后现金。行业、市场和币种暴露使用同一组权重聚合；相关性与风险贡献直接复用既有组合回测结果，不重新实现协方差算法。

账户中出现本地目标组合未覆盖的持仓时，整个候选批次阻断。最大回撤、当日损失、交易频率、相关性或风险贡献越限时同样阻断整个批次。总暴露和集中度限额可以按确定性规则缩减目标；风险调整目标只能小于或等于原目标，不能增加任何标的暴露，缩减部分回到现金。M5 只生成候选调仓，不批准、不提交也不路由订单。

评估使用 `portfolio_risk_assessment` 审计事件和 `aiqt.portfolioRiskAssessment` 记录。事件身份与 `recordHash` 由规范输入和结果生成，相同输入幂等回读；读取时重新校验哈希、Stage 4 工作流绑定、权重和安全字段。研究运行现有导出已经包含 `auditEvents[]`，因此不增加第二套导出或存储链。

## 安全边界

- `paperOnly=true`
- `liveTradingAllowed=false`
- `orderSubmissionEnabled=false`
- `routeExecuted=false`
- `liveBlockedBoundary=true`

M5 API 不含审批、执行、对账、模式切换或急停方法。组合页面的“运行组合风险评估”只写入评估事件；Stage 4 的订单和成交记录保持不变。分类、操作者和审计内容继续经过敏感信息检查。

## 验收

M5 退出需要同时证明：

1. 当前权重、目标权重、漂移、现金与候选调仓来自同一 Stage 4 账户回放。
2. 当前、目标和调整后组合分别满足权重与现金守恒。
3. 行业、市场、币种、相关性与协方差风险贡献可回读并在组合工作区展示。
4. 账户未匹配持仓会阻断整个候选批次，不能被本地目标覆盖或忽略。
5. 最大回撤、当日损失、交易频率、总暴露和集中度限额形成权威组合级检查。
6. 风险只能缩减或阻断目标，不能增加暴露；阻断时所有候选订单均不可执行。
7. POST/GET 通过真实本地 HTTP handler 与临时 SQLite 验证幂等、哈希、篡改拒绝和安全字段。
8. Web 聚焦/全量测试、Python 聚焦/全量测试、生产构建、隔离 Docker 和真实页面复验通过。

最终回归为 M5 Python `6 / 6`、M5/布局/组合工作区聚焦 `219 / 219`、Python 全量 `798 / 798`、Web 全量 `1089 / 1089`；生产构建与 `git diff --check` 通过，仅保留既知前端 chunk-size 提示。
