# M6 连接器状态复用既有能力与健康证据

M6 不新建连接器注册表、健康服务、权限系统或数据库表。数据源、AI Provider 和执行适配器已经分别拥有设置状态、Provider 注册表、健康探测、状态台账和证据链；M6 只把这些既有事实投影成普通用户可先读懂、专家可继续展开的终端状态。

## 决策

设置工作区的连接器总览固定先显示：

- 当前状态；
- 阻断原因；
- 影响；
- 下一步。

三类连接器继续使用各自权威来源：

- 数据源读取 `marketDataAdapters` 的能力、`providerHealth`、`retryAfterSeconds`、缓存最新时间、凭据要求和只读边界；
- AI Provider 读取现有 `/api/ai-review/providers` 注册表。`configured` 只表示已配置；除本地确定性基线外，没有端点探测证据时必须显示“健康未探测”，不得推导为健康；
- 执行适配器同时读取设置状态、状态台账、CCXT 只读健康探测和既有证据链汇总。通用 `crypto-live` 能力声明与具体 `ccxt-live` 探测证据分别保留，不伪造为同一身份；页面会补充显示只在探测中出现的具体适配器。

数据源能力、权限、冷却、最近成功或状态证据、未决状态和技术下一步进入原生 `<details>`。默认第一屏只显示总览；展开后的宽表只在自身容器滚动。连接器配置、模型地址和凭据摘要只消费后端已经脱敏的字段，浏览器不接收密钥。

所有新版工作区继续复用同一个 `PageHeader`。共享页头根据既有主动作显示当前状态、阻断原因和下一步；完成态、动作禁用态与可继续态不在各工作区重复实现。设置页原先不能工作的静态分区按钮改为页内锚点，静态 AI Provider、假模型、固定本地路径和写死的安全布尔值删除。

## 安全边界

- 设置页的“检查执行适配器”继续调用既有只读健康探测。
- 页面只展示核心服务明确返回的 `liveTradingAllowed` 和必需门禁；没有权威字段时不推断下单提交或路由权限。
- AI Provider 注册表加载不发起模型调用，外部服务仍需逐次授权证据摘要。
- M6 不改变 Paper、Testnet、Production、急停、人工确认、余额、交易所规则、订单状态机或对账逻辑。

## 验收

M6 退出需要同时证明：

1. 九个新版工作区页头均先显示当前状态、阻断原因和下一步。
2. 数据源逐项显示实际能力、健康、凭据边界、冷却、最近缓存证据、未决状态和下一步。
3. AI Provider 使用真实注册表，明确区分本地基线、已配置、未配置和健康未探测。
4. 执行适配器使用设置状态、台账、只读健康探测和证据链，明确显示权限、凭据、最近证据和未决状态。
5. 配置不会被当作健康或授权；无证据时明确显示未加载、未探测或暂无成功证据。
6. 原始能力、权限与技术诊断默认折叠，展开后不造成页面级横向溢出。
7. 深浅主题、键盘可达锚点、折叠控件和语义状态继续复用现有主题与原生控件。
8. Python、Web、生产构建、隔离 Docker 和真实页面复验通过。

## M6 退出结论

截至 2026-07-28，上述八项均由当前代码和可运行证据覆盖。M6 没有增加后端 schema、API、Store、适配器或依赖；唯一新增行为是设置直达时复用既有 AI Provider 注册表加载，并把现有连接器事实接入新版工作区。

聚焦组件与布局回归为 `216 / 216`，Web 全量为 `1090 / 1090`，Python 全量为 `798 / 798`；生产构建与 `git diff --check` 通过，仅保留既知前端 chunk-size 提示。

独立 Compose 项目 `aiqt-m6-acceptance` 使用独立数据卷和 5176 端口，并显式清空交易、生产、AI、Webhook、free-stockdb 与代理配置。真实设置页在 `1280 × 720` 深浅主题下显示数据源 `1/4` 健康、AI Provider `1/4` 已配置、一个纸面适配器就绪、CCXT Sandbox 凭据未配置和实盘阻断；三类详情展开后页面宽度仍为 1280px，控制台 `0 error / 0 warning`。

验收只展开连接器详情并切换界面主题，没有点击执行健康检查、运行研究、AI 评审、保存、执行模式、急停、对账或任何订单动作。原 5173 Testnet 容器未替换、未重启，继续保持 healthy。
