# M1 统一决策契约从自动评估链开始

M1 复用现有自动交易评估路径建立首条统一决策契约，不新建策略引擎。每次完成有效评估后，系统把最近 6 根完整 K 线规范化为带哈希的市场快照，记录规则、风险或 AI 产生的决策提案，再记录经过持仓边界校正后的标准信号。

决策提案和标准信号必须分开保存：例如 AI 提议买入但已有持仓时，提案仍为买入，标准信号为持有。相同市场快照的重复读取只回读已有契约，不产生新判断。快照哈希、策略修订、提案和信号都使用确定性内容哈希，AI 调用结果只作为已记录提案进入后续确定性阶段。

第二个切片把标准信号投影为组合目标，再生成风险调整目标。风险调整只能保持、缩减、清零或拒绝，批准目标不得放大原目标；当日亏损和小时频率边界只拒绝新增风险，不能阻止止损、止盈或其它降低风险的退出。自动交易数量改为消费批准目标与当前持仓的差额，不再在路由前另算一套数量。

第三个切片只在批准目标存在非零差额时生成稳定订单意图。订单意图绑定市场快照、策略修订、提案、信号、组合目标与风险调整目标；测试网和生产路由从执行模式与订单意图 ID 派生原有格式的稳定 `clientOrderId`，并直接消费订单意图中的方向、数量、参考价和名义金额。

第四个切片把纸面、测试网和生产实盘的执行回执统一为订单结果。订单结果始终绑定订单意图 ID，并记录执行模式、状态、成交数量、剩余数量、成交均价和成交金额；测试网与生产结果继续由原路由和原对账状态机推进，纸面模式只补同语义的本地成交结果。

第五个切片让研究运行和其内置回测复用同一市场快照身份：`snapshotHash` 由市场、标的、周期和既有规范化 K 线内容哈希共同派生。历史研究运行在读取时按相同规则补出身份，不迁移数据库，也不改写回测算法。

第六个切片让回测工作区直接读取当前上下文最新研究运行的完整详情，并在可复现性侧栏、证据卡和 Markdown 报告中展示同一 `snapshotHash`。K 线内容哈希继续单独表示数据完整性，不修改回测算法。

第七个切片让 AI 评审直接读取当前上下文最新研究运行的完整详情，并在既有证据审计区展示同一 `snapshotHash`。策略实验的 `snapshotId` 继续作为兼容字段承载相同的规范快照身份，不修改评审算法或外部出站内容。

第八个切片把持仓边界上收为共享的标准信号规则：自动交易的决策提案由统一契约直接标准化，回测的规则提案也经过同一规则后才进入成交模拟。已有持仓不重复买入、空仓不可卖出的语义不再分别维护；回测结束时的强制平仓仍只是模拟结算，不伪装成策略信号。

第九个切片把自动交易既有的账户覆盖检查纳入统一决策契约。Paper 使用本地策略账本形成检查证据，测试网和生产复用交易场所只读覆盖结果；只有检查通过且风险批准差额非零时才生成订单意图，`accountCheckId` 同时参与订单意图身份，未通过检查不能生成委托。

第十个切片保留自动 AI 调用已经返回的审计元数据。AI 决策提案记录 Provider、模型、提示模板版本、输出协议版本、token 用量、延迟和市场快照证据引用；规则与风险提案使用相同字段并对不适用项保留空值。该元数据参与稳定提案 ID，历史回读不重新调用 Provider。

第十一个切片让已记录决策提案可以重新进入既有契约构建器。重放先校验提案内容与 `proposalId`，再用重新计算的市场快照校验上下文；通过后复用原标准信号、组合目标、风险调整和订单意图构建路径。相同确定性输入生成完全相同的契约，过程不读取 Provider 注册表，也不发起新的 AI 调用。

第十二个切片补全标准信号的时间与策略身份。自动交易复用既有 `auto-pct-v1` 策略种类作为稳定 `strategyId`，保留内容哈希修订；信号同时记录 timeframe 周期、所评估的最后一根完整 K 线时间和从评估时刻起一个周期的到期时间。这些字段进入信号 ID，因此后续目标、风险和订单意图都绑定同一信号语义。

第十三个切片让统一订单结果保留费用证据。Paper 使用既有固定费率记录报价币估算费用；测试网和生产优先保留交易所回执中的原始费用币种与金额。基础币或报价币费用可以直接结算，第三币种费用保留原始证据并标记仍需估值；无成交结果不伪造费用。

第十四个切片让自动评估与回测共享完整的决策提案和标准信号构造器。回测规则按截至当前已评估 K 线的不可变前缀快照生成提案，不把未来 K 线纳入当时的证据身份；研究运行仍以整段规范数据快照表示本次回测输入。策略成交记录及研究审计保存 `proposalId`、`signalId` 与信号自己的 `snapshotHash`，可以从回测结果追溯到当时可见的证据链。回测结束强制平仓仍不伪装成策略提案或信号。

第十五个切片把现有 Binance Spot 市价委托的精度、市场限制和余额校验提取为共享准备步骤。Testnet 与 Production 只有在交易对有效、数量和参考价完成 CCXT 规范化、最小数量与最小名义金额通过、余额覆盖且既有急停、会话、未决状态和生产权限检查通过后，才用规范数量生成最终订单意图；准备结果中的市场规则、费率估算与滑点模型进入订单意图身份，路由直接消费相同数量并在提交前重复同一交易场所检查。已记录外部提案重放时把原准备证据作为确定性输入，不重新读取 Provider 或交易场所。Paper 保持本地策略账本规则、既有费率估算和零滑点语义。

当前切片不改变外部适配器、订单状态机或下单安全边界，也不把持有或被拒绝的目标变成空委托。

## M1 退出结论

截至 2026-07-28，M1 的十五个增量切片已经形成并验证完整的 `MarketSnapshot → DecisionProposal → Signal → PortfolioTarget → RiskAdjustedTarget → OrderIntent → OrderResult` 单向契约。自动评估、回测、研究审计、Paper、Testnet 与受控 Production 继续复用现有模型、store、适配器和状态机；已记录 AI 提案及外部准备证据可以离线确定性重放，交易场所规则失败不会生成最终订单意图，风险层和路由层均不能放大批准数量。

Issue #22 仍包含 M2 至 M6 的后续里程碑，因此不因 M1 完成而关闭。M2 后端监控告警、M3 数据质量、M4 AI 研究闭环、M5 真实组合风险和 M6 连接器体验不属于本 ADR 的实现范围。
