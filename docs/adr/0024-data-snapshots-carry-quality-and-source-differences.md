# M3 数据快照携带质量与跨源差异证据

M3 不新建行情仓库、数据融合引擎或研究状态机。它扩展既有 `DataQuality`、研究运行快照、SQLite 行情缓存和设置页能力清单，使同一份规范 K 线在进入研究、回测和缓存前经过一套质量检查，并随研究运行离线回放。

## 决策

市场数据适配器继续使用现有接口。设置状态为每个适配器补充市场、周期、单次历史深度、复权模式、时效语义、凭据要求和只读边界。配置存在不等于健康：可选 free-stockdb 地址只表示“已配置、尚未探测”，不会返回地址本身，也不会被标记为已验证可用。

统一质量检查复用 `normalize_snapshot_bars` 和 `canonical_data_hash`，不再实现第二套规范化。质量契约记录：

- 原始来源、观测时间、最新市场时间和市场日历身份；
- 复权模式、行数、完整性、时效、覆盖率、缺口和警告；
- 重复时间戳、乱序、非法 OHLC、非有限值、缺口、形成中 K 线和过期数据；
- 与快照内容一致的 64 位规范哈希。

结构错误、上下文错配、重复、乱序、非法数值和加密货币或分钟级连续缺口会阻断研究。股票日线缺口、过期和末根形成中 K 线保留为显式警告：现有自动交易路径仍会在账户、AI 和委托前剔除形成中 K 线，并按更严格的周期时效规则阻断，M3 不放宽该边界。当前股票日历是既有静态交易时段模板；日线缺口按工作日识别，节假日误报风险通过日历身份和警告公开，不伪装成交易所完整日历。

研究运行把规范 K 线直接嵌入不可变快照。写入和回读都重新计算内容哈希，生成 `offlineReplay.status=verified`、`networkRequired=false` 证据；断网时可从既有 SQLite 缓存创建同一规范哈希的研究快照。历史运行保持原契约形状，不迁移数据库；只有带 M3 字段的新运行扩展质量证据。

跨来源比较首版只覆盖 A 股日线 OHLCV。报告按共同时间戳比较开、高、低、收、量，分别记录最大相对差异、警告阈值、阻断阈值、重叠率、差异明细和报告哈希。报告固定 `valuesMerged=false`：系统不平均、不覆盖，也不静默选择“更好”的值。材料差异在回测和 AI 之前阻断研究，警告差异允许保留但要求人工复核。M4 才处理进入 AI 研究证据的财务事实双来源验证；M3 不为尚不存在的财务事实模型建立第二套存储。

[free-stockdb](https://github.com/hello245m/free-stockdb) 仅作为可选本地 A 股日线对照源。适配器只调用官方 `cmd=get` HTTP 读取协议，固定只读、仅用于比较，不调用同步、计算或写入命令，不缓存其值来替换主来源。其 MIT 许可和上游来源在本 ADR 保留；未配置、请求失败或质量不合格时报告为不可用，不伪装成一致。

## 安全边界

- 数据检查没有 AI、券商、账户、对账、模式切换或订单方法。
- free-stockdb 地址只在 API 进程内读取，不进入响应、审计或页面。
- 跨源比较从不融合数值，也不能把对照源提升为唯一权威来源。
- 普通测试和 Docker 验收不配置交易凭据，不调用 Testnet 或 Production 写接口。
- 原有自动交易完整 K 线和时效阻断继续生效。

## 验收

M3 退出需要同时证明：

1. 设置 API 和界面展示完整数据源能力矩阵，且“已配置”不冒充“健康”。
2. 冻结数据测试覆盖重复、乱序、非有限值、非法 OHLC、缺口、时效、形成状态、复权身份、日历身份和规范哈希。
3. A 股日线跨源报告覆盖一致、警告、阻断和不可用，并证明没有数值融合。
4. 研究在结构错误或材料差异时于回测和 AI 前阻断。
5. 新研究运行可在断网下从嵌入快照或缓存回放同一规范哈希。
6. free-stockdb 适配器只使用官方只读 GET 协议，地址不外泄。
7. API 契约、Web 组件、全量测试、生产构建、隔离 Docker 和真实页面复验通过。

## 退出结论（2026-07-28）

M3 已按上述七项条件退出。冻结数据聚焦测试 `10 / 10`，Python 全量 `785 / 785`（另含 `752` 个子测试），设置组件与布局聚焦 `212 / 212`，Web 全量 `1077 / 1077`，生产构建通过；仅保留既知前端 chunk-size 提示。

隔离 Compose 项目 `aiqt-m3-acceptance` 使用独立数据卷和 `5174` 端口，显式清空交易、AI、Webhook 与 free-stockdb 配置。API 与 Web 均 healthy，设置状态返回 `4` 个真实能力矩阵条目；未配置 free-stockdb 时保持 `blocked`、`readOnly=true`、`credentialRequirements=[]` 和 `comparison-only`，不会把端点配置误称为凭据或健康。

隔离环境只运行一次 A 股 `600000 · 1d` 研究读取。运行 `run-9134f1622061` 持久化 `120` 行腾讯前复权日线，规范内容哈希为 `d6226c9a4ee0d885ab5f85bc1800ec7bf50012f8d1b752e9d40c9f0fc6c0527a`，研究快照身份为 `673f9d4dc3399c420ac840b993db8101f0bf629770c5276b66624b8394092717`；重启隔离 API 后仍可回读，离线回放为 `verified`、`networkRequired=false`，未配置对照源时差异报告明确为不可用且 `valuesMerged=false`。

真实设置页和研究页均在 `1280 × 720` 下复验：设置页展示核心服务返回的 `4` 行、`7` 列能力矩阵，不再渲染静态 Tencent、Eastmoney 或 Finnhub 健康表；研究页展示来源、复权、时效、覆盖率、跨源状态、完整快照身份和离线回放。两页页面与工作区横向溢出均为 `0px`，浏览器控制台为空。

隔离验收没有配置或调用外部 AI、Webhook、Testnet、Production 或 free-stockdb 写接口，也没有点击研究、保存、评审、模式切换、急停或任何订单操作。原 `5173` Testnet 容器未替换、未重启；验收结束后只删除隔离项目及其临时数据卷。
